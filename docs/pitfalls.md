# 坑清单：每个都会伪装成「模型不行」

这些坑的共同特征：**现象看起来像"模型不会玩"，实际是链路/座位/口径在骗你。**
在做「让模型玩游戏」这类实验时，先要证明"链路能把模型的选择忠实执行"，否则测到的是自己的 bug。

## 一、真机链路六坑（jsnes + 真 ROM）

| # | 坑 | 现象 | 真因 | 修法 |
|---|---|---|---|---|
| 1 | **按键边沿** | 「卡在水管前不动」「选了 jump 却只推进一点点」 | SMB 起跳是边沿触发；连续 `__hold(["RIGHT","A","B"], n)` 时"刚抬起就按下、中间不跑帧" ⇒ jsnes 认为 A 一直按住 ⇒ 整局只跳一次 | 每次按键前先跑 2 帧完全松开（`--pulse-release`）；同座位 32 步从 ~400px → **584px** |
| 2 | **帧缓冲颜色打包** | 天空粉红、马里奥蓝色；或整幅全黑 | jsnes 像素是 **`0x00BBGGRR`**（B 高位）；把底层 ArrayBuffer 直接当 RGBA 还会得到 alpha=0 ⇒ 全透明＝黑屏 | 逐像素按 BGR 拆并置 alpha=255；判据技巧：取一个已知颜色的像素（天空）反推打包顺序 |
| 3 | **PNG color type** | 画面统计"亮度 2.4、96.8% 全黑"，人眼看着正常 | Chrome `canvas.toDataURL` 出 type 6（RGBA，4 字节/像素），自研渲染器写 type 2（RGB，3 字节）；按 3 字节硬解 RGBA ⇒ 全错（真实亮度 138.6） | 解码前先读 IHDR color type 定 stride |
| 4 | **世界 x ≠ 屏幕 x** | "往前看"永远看错位置；进度算不出 | `0x0086` 是世界 x **低字节**（256 回绕）；屏幕 x = `(0x0086 − 0x071C) & 0xFF`；相机过屏幕 x=112 才跟随 | 用展开后的世界 x 做位置/进度；**不能对 Δ 取绝对值**（后退/停下也会被算成推进） |
| 5 | **把自己算进画面** | 状态里永远写"障碍 6px ahead" | "前方障碍"扫描从 `mario_x+6` 起，而马里奥精灵宽 16px ⇒ 扫到自己 | 扫描起点至少 `mario_x+22` |
| 6 | **判据的地面/装饰语义** | 一路狂跳；该跳时不跳撞死蘑菇兵 | ① 背景绿山丘被当"地面" ② 灌木被当障碍 ③ 跑动姿势"脚下 5px 是天空"被判在空中 ④ 坑要晚跳、障碍要早跳（满跳 ~104px 位移，坑沿 55px 起跳会落坑） | 按颜色分级（绿色且矮=装饰）；坑/障碍分开阈值；站地判据用 vy+包围盒；卡住检测兜底 |

## 二、座位/口径七种失败模式（外表都一样：像"模型不行"）

1. **决策粒度必须细于动作耗时**：一步 32 帧（≈80px）而满跳飞 100–140px ⇒ 落点在决策回路之外。
   同一套策略：32 帧/步座位重开 3 次，6 帧/步座位一次过。
2. **座位会悄悄给假能力**：跨决策常按让脚本白得"长按 A" ⇒ 判定"上界"必须与被测对象**同座**。
3. **候选集合/措辞会伪造结论**：5 候选里两个含 A ⇒ argmax 恒 jump（假"塌缩"）；换措辞 ⇒ 恒 go。
   同一状态、同一候选，多一行等义描述就换一种塌缩。
4. **"无状态"控制组设计错了**：抹掉状态后所有 case 折叠成同一条 prompt，"输出常量"只证明确定性、
   不证明状态无关。修法：**用错状态而不是无状态**（stateswap）。
5. **单帧没有速度**：一张截图能告诉你玩家在哪，不能告诉你他往哪走 ⇒ 状态文本要显式标注
   "vertical speed UNKNOWN" 或带上历史动作。
6. **延迟是竞争下的数字**：同一份代码同一天跑出 1387.8 / 2820.9 / 1001.7 ms 均值。
   报延迟必须标「同机同时刻、是否空载」。
7. **准确率会掩盖机理差异**：Laya 与 NanoJev 在 97 例基准上准确率一模一样（=多数类基线），
   但错状态对照下 Laya 翻转 6/97、NanoJev 翻转 0/97——一个读状态、一个状态盲。
   **单看准确率会把这两个模型看成同一个东西。**

## 三、YOLO 标注坑（detect/README.md 有完整数字）

- 真值要读 **PPU 的 spriteMem（64 槽）**，不是 CPU 影子页 $0200（帧末读拿到的是下一帧的位置，
  且 SMB 敌人放高槽位，只读 16 槽会整只漏掉第二只板栗仔）；
- `0xFC` 是空白填充 tile，不当生物像素（否则框比生物高 8–16px）；
- 一个生物会被切成两组（马里奥 16×24+16×8），要先分类再合并「同类、同列、纵向相邻」的组。
- 修正标注读法后 mAP50 从 0.656 → 0.990——**提升来自标注读法，不是调参**。

## 四、Windows/工具链

- 别用 `/tmp/xxx` 当中间文件路径：shell 翻成 `C:\Users\...\Temp`，Python 写的可能是 `C:\tmp`，两边不是同一个地方；
- Playwright 录制必须 `device_scale_factor=1`，否则录出全白帧；
- webm→mp4 要显式 bt709，否则紫偏色；
- 长批跑任务注意执行环境的默认超时（被 300s 上限掐死过）。
