# 架构：五个角色与三种座位

## 1. 五角色分工（本工程的解法）

| 角色 | 实现 | 职责 |
|---|---|---|
| 眼睛 | `detect/`（YOLOv8n） | 画面 → 生物框（goomba / mario），真值来自 PPU OAM 自监督标注 |
| 仪表 | `smb_state.py` | RAM → 语义字段（世界 x、相机、垂直速度、命数、时间、OAM 敌人） |
| 裁判 | `smb_fallback.py` | 画面统计 + RAM → 坑/障碍/威胁判定 → **安全动作集** |
| 模型 | `probe_laya.py`（常驻子进程） | **只在安全集内挑动作**，不做危险判断 |
| 手柄 | `nes_play.py` 的 `ButtonPulse` | 决策 → 按键脉冲：先松 2 帧再按，跳有界 30 帧窗口 |

设计动机：**判断**（这一带危不危险）与**动作**（安全集里挑哪个）是两件事。
实测证明 Laya 前者做不到（危险判定 0/20），后者能做。把两件混在一个 prompt 里问，
测出来的失败无法归因——分层之后才能说清「到底是哪一环不行」。

## 2. 三种座位（`--macro-mode`）

「座位」= 模型看到什么状态、能选什么动作、动作怎么翻译成按键。**同一个模型换座位，结论完全不同**——
所以一切对照实验必须同座位。

| 座位 | 动作集 | 语义 |
|---|---|---|
| `macro` | 向前跑 / 向前跳 / 后退 / 等待 / 原地跳 | 语义宏，自带位移；执行层把选中的键按住固定帧数 |
| `timing`（推荐） | go（继续冲）/ jump（起跳）/ back（退后） | **前进由马达层默认承担**，模型只做时序修正；每条动作是一次原子按压 |
| `rich` | `smb_actions.py` 的扩展词汇（冲刺/走/小跳/大跳/退后…） | 结构化特征全量喂给模型 |

timing 座位的关键教训：若「按住 A」跨决策保持，常量翻跳的大脑只会跳一次（SMB 起跳是**边沿触发**），
画面看着像「链路坏了/模型冻住了」，其实是座位语义给了假能力——**座位必须让两个大脑都只能表达它真正选的东西**。

## 3. 大脑（`--macro-brain`）

同一座位可插不同大脑做对照：

| 大脑 | 含义 |
|---|---|
| `model` | Laya（经 `--adapter` 子进程） |
| `script_guard` | 分工架构：规则层判危险给安全集 + 简化映射（400 步 0 掉命的配置） |
| `ref` | 参照大脑（完整脚本策略，对照上界） |
| `script` | 简化映射 |
| `random` | 随机（下界） |

## 4. 执行层按键语义（ButtonPulse）

- **边沿触发修正**：每次新决策先松全部键 `--pulse-release` 帧（默认 2），否则 jsnes 认为 A 一直按住，
  整局只跳一次（实测同一座位 32 步从 ~400px 提到 584px）；
- **跳有界**：A 最多连续按住 `--jump-window` 帧（默认 30 = 满跳）；超窗后再选跳会先松手重按保证边沿；
- **决策粒度**：一步 6 帧 ≈15px，必须细于满跳飞行时间（100–140px）——粒度 32 帧时落点在决策回路之外，
  任何策略都过不去；
- **开机配方**：真游戏停在标题/菜单页，`--boot "START:6:60,A:4:60,A:4:90"`（键:按住帧:等待帧），每款游戏不同。

## 5. 模型适配器协议

常驻子进程，stdin/stdout 一行一个 JSON：

```
→ {"state_text": "<结构化状态文本>", "candidates": [{"id":"go","text":"..."}, ...]}
← {"choice": "go", "probs": {"go": 0.61, "jump": 0.30, "back": 0.09}}
```

实现参考：`probe_laya.py`（真模型）、`stub_adapter.py`（固定/启发式，自检用）、`random_adapter.py`（随机）。
换模型 = 写一个满足协议的 `--stdin-loop` 适配器，执行层一行不动。
`smb_promptwrap.py` 演示了怎么在协议中间插一层做 prompt 工程（包状态文本、透传回答）。
